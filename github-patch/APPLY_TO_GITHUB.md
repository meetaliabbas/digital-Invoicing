## 4. Environment variables

Configure these for Preview and Production in Vercel:

- `NEXT_PUBLIC_SUPABASE_URL=https://djvozxwzrxxlqmdynwig.supabase.co`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<your Supabase publishable key>`
- `NEXT_PUBLIC_SITE_URL=<the verified deployed site origin>`

The first two are already configured in the Vercel project. Never place a Supabase service-role/secret key in a `NEXT_PUBLIC_*` variable. Confirm the actual canonical deployment URL before relying on `NEXT_PUBLIC_SITE_URL`.

In Supabase Auth → URL Configuration, set the Site URL and add the exact production and preview callback URLs, including `/auth/callback` where required. Test email confirmation and password reset links.

## 6. Data and fiscalization safety

- The Supabase project already contains `tenants`, `tenant_members`, `invoices`, and `invoice_events`, with RLS enabled.
- Security advisor returned no findings during this review. The performance advisor identified one missing covering index; this release adds `invoice_events_tenant_invoice_idx` to the schema file, and the same index was applied to the live Supabase project.
- Test tenant isolation using two separate Auth users and two tenants. Verify that users cannot read another tenant's invoices or write audit events directly.
- The FBR submission route deliberately remains fail-closed. It does not submit real invoices. Do not set `FBR_SUBMISSION_ENABLED=true` expecting a working integration; an approved FBR/PRAL adapter, credentials, idempotency/retry handling and sandbox acceptance remain necessary.
